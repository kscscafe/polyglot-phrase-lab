# Architecture

## 一つの学習フロー

1. Web / iOS / Android の利用者がレベルを選ぶ。
2. Go API が教材JSONから例文を選び、語句をシャッフルして返す。
3. 利用者が並べた語句を送信し、APIがRust採点エンジン（`PHRASE_ORDER_BIN`）へ照合を委譲する。
4. 発音練習の録音は音声エンジンへ渡し、Cが無音区間を検出、C++が基本特徴量を集計する。
5. 学習結果をJavaの復習スケジューラーに渡し、次回復習日を計算する。
6. Rubyで教材CSVを取り込み、C#で公開前のデータ品質を検査する。

## 設計方針

- クライアントとサービスは `contracts/openapi.yaml` のHTTP/JSON契約を共有します。
- 各言語は実際の責務を持つコンポーネントとして配置し、同じ処理を12回複製しません。
- APIの採点結果に、正解文・拼音・日本語訳を含めます。Rustエンジンを未設定の場合はGo内蔵比較へフォールバックします。
- 音声評価はこの初期版では音量・無音などの信号特徴に限定し、発音の正誤を断定しません。
- 教材・アプリ本体の秘密情報は含めません。公開前に依存関係・ライセンス・履歴を点検します。

## 初期版の制約

- APIデータはメモリ上で扱い、永続DB・ユーザー認証は未実装です。
- iOS / Android はAPI連携の薄いサンプルで、配布可能な完成アプリではありません。
- 音声解析は中国語の声調を採点するモデルではありません。
- 全12言語を製品として運用するには、実行環境・CI・セキュリティレビューの追加が必要です。
